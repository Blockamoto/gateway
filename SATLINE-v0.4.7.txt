SATLINE — LOCAL ENGINE v0.4.7

PURPOSE
On-demand forward ordinal sat lineage using Bitcoin on Demand evidence.

INPUTS
- global sat number
- satpoint: txid:vout:offset
- Bitcoin on Demand positional satpoint: {offset}.{vout}.{txindex}.{height}.bitcoin

ALGORITHM
1. For a global sat number, derive theoretical issuance height/offset from Bitcoin subsidy rules.
2. Map that subsidy position into the actual issuance block coinbase outputs.
3. For the current satpoint, ask Bitcoin on Demand spender_lookup for its confirmed spender.
4. If spent, calculate the sat's position in the concatenated transaction input stream.
5. Map FIFO into ordinary outputs.
6. If the position exceeds normal output value, treat it as a fee sat.
7. Map fee sats into the block coinbase stream: subsidy + preceding transaction fees + current fee offset.
8. Continue until an authoritative confirmed-chain terminal state is reached.

SAFETY
- UNKNOWN spender coverage => UNRESOLVED.
- Mempool spends are reported but not advanced as canonical lineage.
- BIP30 duplicate-txid history retains block context and has explicit destruction/ambiguity states.
- Underclaimed coinbase value never creates imaginary sats/outputs.

NO PERSISTENCE / NETWORK
v0.4.7 stores no Satline checkpoints and advertises no Satline peer protocol. Those are later milestones.
