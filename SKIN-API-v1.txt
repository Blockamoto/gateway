BLOCKS ON DEMAND — SKIN API v1

Skins are replaceable HTML/CSS/JavaScript views over Local API v1. A skin does
not receive Core credentials, BOD storage paths or peer sockets.

Key routes:
  GET  /api/v1/status
  GET  /api/v1/meta
  GET  /api/v1/modules
  POST /api/v1/search
  POST /api/v1/fetch
  GET  /api/v1/p2p/status
  POST /api/v1/tx/resolve
  POST /api/v1/prevout/resolve
  POST /api/v1/spender/resolve
  POST /api/v1/address/utxos
  GET  /api/v1/coverage

Validation states in 0.4.1 (unchanged from 0.3.9):
  structurally_checked
  pending_header_validation
  header_anchored
  consensus_validated

Skins should display the state explicitly rather than collapsing all positive
retrievals into one generic "verified" badge.
