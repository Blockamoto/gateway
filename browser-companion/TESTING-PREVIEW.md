2. In PowerShell, run `./browser-companion/Register-PreviewNativeHost.ps1 -Browser Edge` (or `Chrome`). This is a dry run. Inspect the exact current-user key and manifest path.
3. If you choose to register this preview, repeat with `-Apply`. It refuses to replace a preview key owned by another folder. It never changes the production host, browser policies, DNS, default browser/search, or installed profile. Windows native-host registration applies to the current Windows user, not only to the disposable browser profile.
4. Open the companion popup and confirm it reports the preview Gateway version. Open `.gateway`, `0.bitcoin`, `0.sat`, `0.bitmap`, and `0.792435.bitmap`. 6. Confirm ordinary domains, phrases, malformed/leading-zero Bitmap addresses, and non-root URLs stay untouched. No ordinary URL/search text is forwarded to the native host. A newer tab navigation cancels a pending handoff.

Chrome/Edge require a native-host manifest, extension allowlist, and Windows registry location; the protocol uses UTF-8 JSON with a 32-bit native-endian length. See [Chrome native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging), [Edge native messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging), and [Chrome webNavigation permissions/events](https://developer.chrome.com/docs/extensions/reference/api/webNavigation). This companion adds `webNavigation` for main-frame resource handoff and requests no broad host permissions.
