# 0.8.0 recipe integration map

This is an implementation map, not a claim that any part of the new engine is complete. Keep the 0.7.9 data and UI operational throughout. A built-in is migrated only when its recipe actually controls its source, conditions, state transitions and outputs; selecting an old complete index by name or opcode is not migration.

## Contract and identity

- Store a versioned typed recipe with source/fact requirements, origin and coverage mode, explicit dependencies and named exports, expressions and filters, projections, keyed lookups, ordered state/transitions and output schemas. Validate names, types, bounds, dependency cycles, state initialization and primitive capabilities before saving or running. A capability catalogue describes these same operators to both compiler and GUI. Reject unknown operations and unsupported compositions with a path-specific error.
- Separate track ID/name and category placement from executable semantics. Compute a canonical semantic hash from the compiled definition and pinned operator/parser versions; exclude display name, ID and placement. Renaming must preserve behavior. Persist the exact recipe and hash with each run and checkpoint, so editing a recipe cannot change an already running job. If semantic hash or dependency lineage differs, keep existing data readable and require an explicit new generation or rebuild; never relabel old results compatible.
- Define expression value types and missing/error semantics, including lossless CBOR metadata traversal (integer width, bytes, text, arrays, maps, duplicate keys and malformed input). Preserve original metadata and distinguish absent, invalid and unsupported values. Enforce budgets and cancellation. Metaprotocol is Ord tag 7; metadata is concatenated tag 5 bytes, already retained by `ord_envelope.go`. Parent declarations are claims until authenticated proof.

## Concrete hooks

1. **Catalogue and persistence.** `index_catalog.go` presently returns global static `indexDefinition` values and `findIndexDefinition(id)` has no profile context. Add a profile-aware recipe registry/resolver, with immutable recipe snapshots and safe IDs; wire the app-scoped callers to it rather than using process-global mutable definitions. Status currently adds Bitmap definitions in `index_runtime.go`; expose compiled custom and built-in definitions through the same view. Freeze existing `RuleHash`, schema, IDs and store readers for old generations; adapter reuse needs explicit semantic equivalence and parity evidence, otherwise make the new generation separate. Existing `index_store.go` validates hashes and identity at read time, while UTXO, address, Sat and Bitmap have different specialized stores.
2. **Admission and scheduling.** `normalizeIndexRunRequest` and `planIndexRun` in `index_run.go` hard-code IDs, ranges, stateful genesis and Bitmap requirements. Replace these decisions incrementally with compiled capabilities and explicit dependencies, not names. `index_run_worker.go` has an `indexRunExternalConsumer` interface (`NextHeight`, `Reconcile`, `Apply`, `Checkpoint`, `Close`), a common worker and `openRunConsumer`; it is a useful initial adapter seam for the interpreter. It currently sorts by `runConsumerOrder` and contains Bitmap-specific paths: plan real dependency DAGs, topologically order same-height consumers and wait for committed matching dependency exports, including earlier saved/backfilled blocks. A category is never a dependency. Preserve admission revisions, per-consumer frontiers, independent Live/Out targets, cancellation and final selected-chain/publication guards. Outcome-only and snapshot inputs need explicit source capabilities; do not force a raw-body fetch.
3. **Source sharing.** `index_run_worker.go` prepares a block and optional `inscriptionBlockResult` once per cohort; `index_resolved_ingestion.go` also fans out verified fetched bodies to armed, admitted tracks. Replace its hard-coded extraction ID checks with compiled fact requirements while preserving ownership guards, source verification, bounded deferred spool, and no writes before origin. Fetching or viewing must never arm a track. Use complete inventory receipts in `inscription_index.go`; a partial occurrence set or empty unknown result is not a complete scan.
4. **Outputs and durability.** Add a generic typed table/view storage adapter with deterministic rows and keys, bounded scans, snapshot-pinned queries and explicitly recorded coverage, including evaluated empty blocks. Keep sparse disjoint coverage separate from continuous prefix and state snapshots. An interpreter must stage all rows, ordered state and dependency fingerprints, write immutable data, sync it, then check admission, selected chain and dependencies again before atomically publishing the head. `index_store.go` and `bitmap_development_store.go` show existing commit/sync patterns; do not conflate their formats. Reorg recovery must restore a valid ancestor or state savepoint, invalidate descendants and retry with the correct source lineage. Verify sparse anchors independently; a current high head does not authenticate disjoint history. Cache authenticated unchanged prefixes rather than repeatedly walking them.
5. **API and query.** `index_interface.go` routes `/api/v1/index/*` with bounded JSON and exposes definitions, plan/build, status, query and lookup; introduce versioned recipe create/validate/read/import/export endpoints and generic committed-table queries using the same compiler. Bound request/row sizes, cursor and result counts. Provide dependency export descriptors and coverage/evidence status, not raw internal paths. The `index_export*.go` path pins snapshots and reports completeness/missing evidence; integrate generic output there only with equivalent snapshot guarantees.
6. **Presentation.** `ui/shell/indexes.html` loads the timeline/workspace scripts; `gateway_shell.go` explicitly allowlists assets. `index-timeline.js` hard-codes `groupOf`, category names and several identity-specific tracks; `index_layout.go` separately validates fixed parents. Extend both to a persisted presentation model with user-defined categories/children and cycle/size checks, distinct from recipe dependencies. Keep existing saved order and category migration. Add a Recipe tab in the current inspector and a guided constructor backed by the compiler catalogue and one typed model. Raw JSON edit/import/export and guided edits must round-trip the same model; show path-specific diagnostics, unsaved changes, dependency/export choices and origin/state implications. Capture request revisions so stale async results cannot override newer edits or transport intent. Hover/navigation remains read-only.

## Increment order and evidence

1. Land contract, semantic hashing, catalogue, validation, and a profile-scoped registry with no changes to old heads. Test ID/name independence, predicate changes, malformed JSON/CBOR and unsupported combinations.
2. Integrate a general inscription-fact recipe through the real scheduler, generic durable table and query path. Author metadata, metaprotocol and property/key-value filters in the actual GUI, then an explicitly dependent child consuming exported parent rows. Test empty blocks, disjoint ranges, backfill, pause/restart, Live/finite Out, reorg and dependency changes on synthetic and bounded authenticated fixtures. This proves a vertical slice, not full acceptance.
3. Express every enabled built-in and independent retained layer as compositional recipes and move actual derivation into reusable typed domain primitives. Stateful UTXO, FIFO Sats, address projection, TXIO and Bitmap proof/winner ordering require explicit state, inputs and outputs; preserve exact proof routes and validated-only Parcel publication. Run paired 0.7.9/new-engine parity over the same source blocks and compare records, coverage and recoveries. A specialized physical adapter is acceptable; a recipe that merely chooses a bespoke whole-index implementation is not.
4. Finish arbitrary track hierarchy and catalogue-driven authoring for every operator needed to recreate built-ins. Test JSON/guided/import/export round trips, useful errors and UI interaction without indexing side effects. Run existing Go/JS/browser suites plus new focused integrated tests; exercise the app visibly in Chrome and produce the isolated portable preview through the existing build/audit process. Record fixture limits and explicit legacy migration boundaries. Do not call the release complete until every row in the parity matrix is demonstrated.
