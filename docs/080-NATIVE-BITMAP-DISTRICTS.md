# Standard Districts as an executable recipe

`recipes/builtins/bitmap-districts-standard-v1.json` now drives the enabled
native Standard District writer. The same document can be copied into a saved
ordered reveal/table recipe. It composes ordinary byte/MIME/decimal operations,
branches, keyed reads and writes: candidate recognition, exact claim grammar,
decoder results, target-height checks, eligibility and first-winner selection
are in JSON.

The native adapter supplies the admitted complete occurrence inventory and
maps typed `winners` / `candidates` rows to the existing ordinal trees. It checks
source identities and the retained row schema, maintains physical reverse keys
and counts, and uses the existing flush/publication fences. It does not choose
claim grammar or select winners. The legacy evaluator remains a test oracle;
inspection-only legacy profiles and the remaining Parcel path retain their
existing gates and behavior.

The native binding combines the admitted reveal profile, typed reveal profile,
Standard profile hash, physical blocator codec and actual program fingerprint:
`426dd8721c0b74b63a7f7e0083f338c2201e231bb16742c0ea84a73487cbf9af`.
Existing Standard profile hashes, candidate serialization, COW page roots,
checkpoint hashes, queries and recovery remain unchanged. The native inspector
exposes the complete document as executable metadata after the frozen rule
identity is established. No data migration or legacy execution enablement is
introduced.

Saved copies use the general typed-table storage and query contract. On verified
block 792435, every saved candidate/winner logical row matches the frozen native
evaluator. Saving a changed suffix rule produces a different fingerprint and a
covered empty result on the original `.bitmap` fixture. The saved run starts no
native District, Inscriptions, Coin or Sat writer. Generic saved rows and native
physical candidates have their explicit storage representations.

Differential checks compare complete native heads, page roots and checkpoint
references on a malformed/duplicate/case/whitespace/overflow/non-ASCII corpus,
across a restart and retained reorg, and on real block 792435. The focused
native/saved/customization set passed in 4.382 seconds, including the benchmark.
Admitted synthetic protocol fixtures and sparse selected-header fixtures are
separate from full consensus or full-chain replay claims.

A single fresh-root sample on that real block measured 82.73 ms and 19.10 MB
cumulatively allocated for the old evaluator, versus 83.63 ms and 20.47 MB for
the recipe. It includes extraction and durable native publication, excludes
source acquisition and peak resident memory, and does not establish full-chain
throughput. Actual District JSON also round-trips through the guided editor and
the real-DOM table controls.

Validated replay Parcel composition, broader typed incoming checkpoints and
complete isolated-preview acceptance remain open.

The wider Bitmap/Parcel/reveal-table suite passed in 425.889 seconds: 210
passes, four skips, no failures. It includes retained/pruned chain storage,
producer isolation, target coverage, replay routes and legacy generation gates.
The temporary audit is `gateway-080-district-recipe-regression.jsonl`.
The production build passed after the final source changes.
