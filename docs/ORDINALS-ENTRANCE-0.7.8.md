## Approved changes

The five houses are Blocks, Transactions, Addresses, Ordinals and Bitmap.
Transactions displays **TX ID Locators**, **IO Links**, Values, Scripts and
UTXO. The first two are display names; their existing machine IDs, stores and
execution choices remain unchanged.
Ordinals contains Sat Ranges and Inscriptions, with the same separate execution
IDs, stores, arming, Live and history choices. This is a navigation move only.
It changes no scanning, retention, format, lifecycle or efficiency policy.
Parents remain compact and default closed, with truthful compressed child
overviews; opening a parent reveals its existing mini-only children and details.

Saved layout schema 1/2 files project the former root Inscriptions position to
Ordinals and move the former Transactions Sat child into that house. Explicit
new Ordinals order takes precedence. Projection preserves revision and file
bytes on reads; new saves use the authoritative current parents. Other saved
positions, identities and index choices remain intact.

Every header reserves the same help, dependency, beacon and Arm stations, with
Arm at the far right. Missing controls leave blank stations. The shared label
rail protects readable names and hit targets; ruler, data lanes, scrollbar and
playhead share its offset. Vertical row sizes and the green selection edge stay.

Headers uses the shared radiating beacon. Its direct independent pause/resume
behavior remains separate from consumer Arm and the master Play/Pause transport.
The enabled appearance describes policy, not proof of freshness or caught-up
state. Existing network status supplies truthful paused/disabled/mirroring,
waiting and error context without a second background poller.

A brief code-native entrance trial marks an eligible visible Home arrival:
stone-arch outline, lantern light, parchment brightening and a thinning frame.
It is decorative and pointer-transparent, with no camera sweep, zoom, startup
gate, network dependency or extra assets. It runs once per tab session and
skips resource deep links, reload/back-forward, hidden loads, setup and dialogs.
Input, navigation or hiding dismisses it immediately, including input in the
same-origin workspace. Reduced motion uses an instant or minimal fade and
cleanup fails open. The existing setup entrance is not doubled.

The fifth article is normal-browser Bitmap handoff. Canonical District and
Parcel addresses pass through the shared parser and authenticated native
activation. Exact direct address-bar navigation is handled separately from
supported search recovery. Namespace status is refreshed through the native
handshake; malformed addresses, ordinary URLs and ordinary search phrases stay
outside resource validation. Existing Bitcoin, Gateway and Sat routes remain.

The candidate bundles a separately identified preview Companion and native
host. Its portable marker and shared `blocks-on-demand-data` profile bind it to
this candidate, not an installed/default Gateway. Registration is an explicit
opt-in step under a separate host name; the normal setup routing action is not
used. No installed native-host keys, protocol associations, namespace routing,
browser profile or extension registration are overwritten by verification.
The bundled Companion follows only the package's default owned profile.
An explicit `Preview.ps1 -ProfilePath` override remains usable for standalone
tests but does not redirect this native host; it is not automatically a
Companion-compatible session. Opt-in registration checks the default runtime.
Production routing enable/disable and native registration actions are blocked
by the preview's authoritative backend, including explicit-consent requests.
The setup screen shows the separate preview instructions and disables those
production actions. Normal release behavior is unchanged.
