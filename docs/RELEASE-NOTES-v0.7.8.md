# v0.7.8: Bitmap Districts

Release preparation for Gateway 0.7.8, following v0.7.7 Sats. This document describes the current source scope; it does not establish that a release has been published or that a particular package has passed acceptance.

- **Bitmap Districts Standard V1** evaluates the fixed [Bitmap rules](https://github.com/Blockamoto/bitmap/blob/335958311eb1c8ce4d14c48bc5c21d23c7a4b134/README.md). Fresh processing starts at block 792435 and proceeds in order, with authenticated checkpoints. A browsed block can show its selected District inscription and reveal location when saved coverage is available. Ownership and inscription numbering require separate evidence.
- **Parcels are disabled** pending further Ordinals and parent-provenance validation. Their normal interface entries are hidden and new, restored and resumed processing is blocked. Definitions and saved records are retained, with passive backend read and export compatibility. A parent tag alone does not prove the required child relationship.
- Both Bitmap chains, custom rule editing, comparisons and execution of earlier Bitmap generations are disabled. Existing evidence remains inspectable under its original identity; old checkpoints are not silently migrated to the current District index.
- Inscriptions and District saved indexes can be exported using native blocators or, where the required local evidence is available, conventional inscription IDs. The export reports its saved scope and does not start indexing or fetch missing history. See [saved index exports](INDEX-EXPORTS-0.7.8.md).
- Complete verified blocks obtained through indexing or normal exploration are offered to applicable already-armed tracks. Sparse facts do not imply contiguous coverage, and stateful tracks only advance with their required prior state. Raw body retention remains independent. See [verified-block ingestion](SPARSE-INDEXING-0.7.8.md).
- Transaction-ID location is an explicit **TX ID Locators** track; retaining Raw Blocks alone does not construct the reverse transaction lookup. Values and ScriptPubKeys may be selected independently of IO Links.
- The workspace groups related tracks and keeps Arm, Live, Start, Pause and Resume choices explicit. Flow and relationship views explain missing evidence; unresolved spending evidence does not prove an output unspent. Reading a view does not start an index build.

Gateway verifies block identity and selected-chain context but does not provide full Bitcoin consensus or script validation. Missing history remains unknown, and bounded local fixtures do not establish whole-mainnet indexing time, memory or storage requirements. Satline history tracing and Gateway peerhood remain disabled. See [indexing](INDEXING.md), [testing](TESTING-0.7.8.md) and [status](STATUS.md) for scope and recorded evidence.
