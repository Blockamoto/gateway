# Transaction update local testing

This guide covers the 0.7.3 development executable. No release or hosted updater activation is implied. Use a separate profile for review so existing settings and indexes remain available to your installed client.

- Open a known block in the global address field, for example `840000.bitcoin`. The right viewport should show every transaction in a BitFeed-style map, sized by output sats on a logarithmic scale. The left Details pane retains verification and block information.
- Select a transaction from the map, the list or a positional address. Its Mempool-style input/output value flow appears automatically in the viewport, with transaction details on the left. Unknown input values and fees must remain unknown; previous output zero must remain zero. **Back to block** returns to the containing block. Inscription badges attach only to verified reveal outputs; unresolved placement is listed separately and is not a claim of current ownership.
- Inscription-bearing transactions show their first inscription as a bounded passive preview or a badge. Open the inscription from Details to view content on the isolated origin. The square viewport has a fullscreen control; Escape returns without moving the playhead.
- Enter an inscription position such as `7i0.840000`. A conventional inscription ID uses a saved locator when available; an unknown location offers a contextual reveal-block hint. There is one global address field.
- In Inspector, enable **Index as you browse** separately for Transaction Index and Inscriptions. Both are initially off. Reopen a validated block: enabled outputs persist their lean records; disabled outputs do not. Cached bytes and index records are separate.
- Browse separated blocks and inspect their timeline coverage. Gaps stay visible. Browsing must not start a range job or advance a sequential build checkpoint. Restart and confirm saved policies and exact coverage survive.
- Build a Transaction Index range, or choose related transaction locators when building inscriptions. The retroactive related-locator action belongs in the Inscription inspector. Gateway peer lookup and later indexes stay locked.
- The compact single-lane tracker is the initial view. Its playhead, ruler and zoom share the full timeline state. Zoom past a known block to reveal ordered transactions in place, then outputs, then output-local sat offsets; use the breadcrumb to return to a parent. An unknown child count must stay unknown. Expand into index tracks and collapse again: zoom and build selections survive; scrub requests wait for the playhead to settle. Ghost bands indicate possible coverage, not stored data. Sat offsets identify positions in a verified output, not global sat numbers or current owners.
- Drag the divider between Details and the viewport. Blocks and inscriptions remain square; transaction flows can use a wider panel. Drag a map or flow to pan, use wheel/pinch to zoom around the pointer or finger midpoint, and use **Fit view** to see the full diagram. Returning to a resource restores its view.
- In both compact and expanded timelines, wheel over a lane to zoom at the pointer; horizontal trackpad movement or Shift-wheel pans. Click a lane to move the playhead, drag its background to pan, and drag the top ruler or playhead to scrub. Shift-click and Ctrl/Command-click edit indexing selections; dragging must leave those selections intact. Alt-wheel changes track height. Space-drag moves horizontally, vertically and diagonally.
- Check desktop and narrow windows, light and dark themes. Details scroll within their pane, the timeline remains docked, and the top-right status popover must not expand the page.

The test build remains unsigned. Content fetching depends on an available Bitcoin provider and known block locations. Reveal extraction does not establish global inscription numbers, current ownership or parent-child provenance. Full release checks are separate from this local review.

The Details/Inspector redesign is a separate proposal in [Workspace pane design](DESIGN-WORKSPACE-PANES.md); this refinement does not implement that broader reorganization.
