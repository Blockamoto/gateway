# District real-block differential

The opt-in `bitmap_common_differential_080_test.go` connects the existing
Gateway block verifier and complete inscription extractor to the experimental
common engine's District recipe. It reads the **owned copy** of the 0.7.8
baseline fixture and committed replay output; it does not start a client or
write to that profile, the archived bodies, or either reference worktree.

The test pins the fixture manifest, headers and baseline executable identity,
checks each real block with Gateway's verifier, and requires the extractor's
complete-inventory receipt before supplying every reveal in transaction-wide
order. For every height, it verifies the 0.7.8 Standard profile fingerprint,
selected and parent hashes, commitment chain, complete coverage and ordered
winner blocators. It looks up each winner's district in the native authenticated
winner tree and compares cumulative winner counts. It also verifies that the
engine rejects a block with incomplete reveal evidence without advancing its
head.

The strengthened test passed on 2026-10-26 using Go 1.27.1: **32 blocks,
64,767 transactions, 12,457 complete extracted inscription occurrences and
three ordered District winners** matched at heights 792435–792466. The owned
baseline fixture and output are generated by the two-phase helper described in
[storage/BASELINE-078.md](storage/BASELINE-078.md). Its binary is pinned to the
documented 0.7.8 performance candidate; its precise source revision has not
been independently established.

To reproduce, first prepare **and complete** a fresh owned baseline as described
in that document. Then, from the checkout root with a complete Go toolchain:

```powershell
$env:GO111MODULE = 'off'
$env:CGO_ENABLED = '0'
$env:GATEWAY_080_078_FIXTURE = (Resolve-Path 'build/baseline-078-owned-01').Path
go test -tags gateway_district_diff -run '^TestDistrictRealBlockDifferential080$' -count=1 -v -timeout=10m .
```

The environment variable must point to the completed owned directory containing
`baseline-result.json`, the copied manifest/headers/archive, and the native
`replay/00-baseline` output. Without it, the optional test skips. The build tag
keeps the bridge out of normal application builds and tests.

This is a narrow differential against existing Gateway extraction and saved
0.7.8 outcomes. The header fixture is pinned, but neither this test nor the
engine performs full Bitcoin consensus validation. The small sample does not
prove general Bitmap/Ord compatibility, alternate charset behavior, missing
or corrupt evidence handling beyond the cases checked, reorganizations,
production storage behavior, performance, or user-defined index coverage.
The common engine itself relies on its caller to authenticate the supplied
blocks and complete reveal inventory.

For an optional downstream backend experiment, set
`$env:GATEWAY_080_078_EXPORT = (Join-Path (Resolve-Path build).Path 'district-verified-32-01.json')`
before running the test. After every differential assertion passes, the test
writes a new JSON file directly inside `build/`; it refuses to overwrite an
existing file or write inside the fixture/profile. Schema version `1` contains
fixture/header/binary hashes, `blocks` (the ordered common-engine inputs) and
`receipts` (the matched per-block outcomes, including empty outcomes). Bodies
use Go's standard JSON base64 representation. The exported JSON is a test
handoff, not an independently authenticated Bitcoin proof; verify its identity
and provenance before reuse. The above run produced a 17,623,957-byte file with
SHA-256 `d3f01991fcfff748fe15aed0c1828d16f18c6e9fb4e8f307011541a02d7ef12d`.
